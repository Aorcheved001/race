## 3. Code Modification Rules

### 3.1 What CAN be modified safely

| Area | Rule |
|------|------|
| `code/**/*.c`, `code/**/*.h` | Application logic - free to modify |
| `libraries/zf_driver/**` | Driver layer - modify with caution, test hardware |
| `libraries/zf_device/**` | Device drivers - same as above |
| `libraries/zf_common/**` | Utilities - generally safe |
| `libraries/zf_components/**` | High-level components - safe to modify |
| `user/*.c`, `user/*.h` | Core entry points - safe to modify |
| `headless_build.bat` | Build/flash script - safe to modify |
| `serial_reader.py`, `sync.py` | Tool scripts - safe to modify |

### 3.2 What MUST NOT be modified

| Area | Reason |
|------|--------|
| `libraries/infineon_libraries/iLLD/**` | Infineon official driver - DO NOT TOUCH |
| `Debug/makefile` | Auto-generated by ADS - will be overwritten |
| `.metadata/**` | IDE workspace metadata - may corrupt workspace |
| `.cproject` | Build configuration - edit via ADS IDE only |

### 3.3 Coding Style

- Follow existing KISS style in the codebase
- Variable names: descriptive, snake_case (`wheel_speed_mps`, `target_yaw_rad`)
- Function names: module_prefix_action (`motor_init()`, `Ins_update()`)
- Header guard pattern: `FILENAME_H_`
- Use `// TODO:` or `// AI:` markers for AI-generated code that needs review

### 4.2 Sync Tool Details

```bash
python tools/sync.py              # Dry-run preview (see what changed)
python tools/sync.py --force      # Actually sync D -> E
python tools/sync.py -f           # Short form
python tools/sync.py -v --force   # Verbose: show all files
```

What sync does:
- Copies `.c` and `.h` files from `D:\race\...\code\`, `user\`, `libraries\`
- Copies root config: `.cproject`, `.project`, `Lcf_Tasking_Tricore_Tc.lsl`
- **Does NOT copy**: Debug/, .metadata/, tooling scripts, docs, .bat, .py
- Compares file size to detect changes (fast, no content diff needed)
- Safe mode (default): shows DIFF but won't overwrite; use `--force` to apply

### 4.3 One-Command Shortcuts

```bash

```

## 6. Key Technical Context

### 6.1 Multi-Core Architecture

- TC377 has **3 CPU cores** (CPU0, CPU1, CPU2)
- CPU0 is the main core running `core0_main()` in `user/cpu0_main.c`
- ISR routing via `user/isr.c`

### 6.2 Interrupt System

- Base tick: **1ms** from STM via PIT
- Tasks polled in main loop via `InterruptTasks_Poll()` in `interrupt.c`
- Time slots: 1ms, 2ms, 4ms, 8ms, 16ms, 40ms

### 6.3 Data Flow Diagram

```
[IMU660RA] --> imu660.c --> Ins_update() --> INS_State {x,y,yaw}
[Encoder]  --> encoder.c --> wheel speed      -->
[Magnetometer] ------------------> mag_yaw     -->
                                                  |
                                            [EKF Fusion]
                                                  |
                                    +-----------------------+
                                    | send_pos_to_host()     |
                                    | "imu_yaw:g,m,e\r\n"    |
                                    +-----------+-----------+
                                                |
                                        [wireless_uart]
                                        [UART2 @ 115200]
                                                |
                                              COM24 (PC)
```

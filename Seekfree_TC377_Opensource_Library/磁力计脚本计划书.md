# 磁力计 2D 离线校准上位机脚本计划书

## 1. 项目目标

在大车平行转向结构上，实现一套用于水平面 2D 磁力计离线校准的上位机脚本。脚本需要完成串口自动发现、数据接收、实时绘图、动作质量判断、自动保存、离线拟合、参数生成和校准后验证。

当前固件采用离线校准方案：C 端每帧读取磁力计原始值，使用 `code/ins/calibration_params.h` 中的硬铁和软铁参数进行修正。上位机脚本必须围绕这个链路设计，避免 raw 数据、calibrated 数据、旧参数文件混用。

最终目标不是做 3D 翻转校准，而是面向大车实际可执行动作，完成可靠的水平面 XY 磁力计 2D 校准。

## 2. 当前 C 端数据链路约束

固件里真正生效的磁力计参数文件是：

```text
code/ins/calibration_params.h
```

不要引用工程根目录下可能存在的旧 `calibration_params.h`。后续所有脚本读取、写入、验证都必须默认指向 `code/ins/calibration_params.h`。

C 端校准公式为：

```c
mx_raw = raw_x - MAG_HARD_IRON_X;
my_raw = raw_y - MAG_HARD_IRON_Y;
mz_raw = raw_z - MAG_HARD_IRON_Z;

mx = mx_raw * M00 + my_raw * M01 + mz_raw * M02;
my = mx_raw * M10 + my_raw * M11 + mz_raw * M12;
mz = mx_raw * M20 + my_raw * M21 + mz_raw * M22;
```

Python 端必须使用等价公式：

```python
corrected = (raw - bias) @ soft_iron.T
```

C 端存在两种发送函数，脚本必须明确当前正在接收哪一种：

```c
imu_mag_send_raw_data_to_pc();          // 发送 imu660.data_Raw.mag_x/y/z，用于正式拟合
imu_mag_send_calibrated_data_to_pc();   // 发送 imu660.data_Ripen.mag_x/y/z，用于校准后验证
```

正式生成校准参数时必须使用 raw 数据。calibrated 数据只用于验证，不能直接作为正式拟合输入。

## 3. 本次实测暴露的问题

### 3.1 raw 和 calibrated 混淆

之前日志文件名和文件头固定写 raw，但 C 端实际可能已经切到 calibrated 发送。这会导致分析时把校准后数据当成原始数据，进而得到错误的硬铁和软铁参数。

脚本方案：

- GUI 必须有数据模式选择：`RAW 采集 / CALIBRATED 验证`。
- 保存文件名必须带模式：
  - `mag_raw_YYYYMMDD_HHMMSS.txt`
  - `mag_calibrated_YYYYMMDD_HHMMSS.txt`
- 文件头必须写明模式、C 端期望调用函数和参数文件路径。
- 如果选择 RAW 模式，但数据中心明显接近 0 或半径已经接近固定值，脚本要提示“疑似接收到 calibrated 数据”。
- 如果选择 CALIBRATED 模式，但数据中心接近旧 hard iron 或椭圆偏移很大，脚本要提示“疑似仍在发送 raw 数据”。

### 3.2 参数文件混用

工程里可能同时存在根目录 `calibration_params.h` 和 `code/ins/calibration_params.h`。真实固件包含的是 `code/ins/calibration_params.h`。

脚本方案：

- 所有脚本默认参数文件固定为 `code/ins/calibration_params.h`。
- GUI 首页显示当前读取到的 hard iron、soft iron 和 field strength。
- 如果发现根目录也有 `calibration_params.h`，只做提示，不允许自动使用。
- 写入参数前弹窗确认目标路径。

### 3.3 自动选窗容易选到局部弧段

之前只看残差和简单覆盖率，可能把局部弧段误判为高质量窗口。实际局部弧段也能拟合出很低残差，但不能代表完整 360 度磁场。

脚本方案：

自动选窗必须同时检查：

```text
方向桶占用 >= 34/36
最大航向缺口 <= 30 deg
环形角度跨度 >= 330 deg
unwrapped 角度跨度 >= 330 deg
校正后半径比 <= 1.15
残差 <= 3.0%
```

窗口报告必须输出：

```text
samples[start:end]
样本数
残差
半径比
方向桶数量
最大角度缺口
角度跨度
Z 轴范围
是否通过
拒绝原因
```

### 3.4 停顿段和旋转段混在一起

这次 90 度停顿验证里，粗切窗口把旋转过渡段混入停顿段，导致半径标准差和 yaw 范围被放大。实际应先识别平台段，再统计停点。

脚本方案：

- 验证模式下增加“自动平台段检测”。
- 使用滑窗判断 yaw span、XY 标准差、半径标准差。
- 识别出的停顿段单独统计。
- 旋转过程单独统计，不混入停点均值。
- 对角度接近的停顿段不强行合并，先显示为多个平台段，再让用户确认是否合并。

### 3.5 半径不能只从原点算

校准后数据中心不一定精确为 `(0, 0)`。半径评价应优先从拟合中心计算，不应只用原点半径。

脚本方案：

验证报告同时输出两组指标：

```text
原点半径：用于直观看固件输出是否接近 0 中心
拟合中心半径：用于评价真实圆度
```

合格判断以拟合中心半径为准。

### 3.6 当前软铁参数方向和缩放存在问题

用当前固件参数反推这轮 calibrated 数据得到 raw，再做 2D 拟合，得到的理想参数与当前参数有明显差异：

```text
当前固件参数：
XX = 1.002607
XY = -0.026773
YY = 0.998833
hard_x = -163.62
hard_y = -207.03

反推 raw 后理想 2D 参数：
XX = 0.941612
XY = +0.020490
YY = 1.067059
hard_x = -153.54
hard_y = -252.30
field = 1359.06
```

这说明当前参数的非对角项方向和缩放都不够理想。正式修正不能靠 calibrated 数据二次反推，必须切回 raw 重新采集。

脚本方案：

- 新参数生成前必须检查输入数据模式为 RAW。
- 如果用户强行用 calibrated 数据拟合，脚本只允许生成“诊断报告”，不允许写入固件参数。
- 诊断报告可以做反推分析，但必须标注“不能作为正式写入依据”。

### 3.7 Z 轴变化会限制 2D 校准效果

本次 90 度验证中，rawZ 在不同停点变化很大，约从 `-726.8` 到 `-1349.6`。这说明存在车体姿态变化、周围 3D 磁干扰或安装位置磁场耦合。

即使理想 2D 参数能把 XY 椭圆明显拉圆，仍可能因为 Z 轴和姿态变化造成不同方向 XY 投影半径不一致。

脚本方案：

- 验证报告必须显示每个停顿段的 Z 均值和 Z 标准差。
- 如果不同方向 Z 均值差超过 500，报告中标为“2D 校准受 3D 效应限制”。
- 不建议对大车强行做 3D 翻转校准。
- 若 Z 变化过大，优先建议检查磁力计安装位置、附近铁磁材料、电机线束、车体倾斜和测试场地。

## 4. 推荐动作设计

### 4.1 正式拟合动作：RAW 连续旋转

用途：生成新的 2D 校准参数。

要求：

1. 固件切到 `imu_mag_send_raw_data_to_pc()`。
2. 上电后静置 5 到 10 秒。
3. 开始采集 raw。
4. 人推大车做连续、匀速、水平旋转。
5. 推荐动作：
   - 顺时针完整 360 度。
   - 逆时针完整 360 度。
   - 场地允许时重复一轮。
6. 不要使用电机驱动。
7. 不要在单个方向长时间停顿。
8. 不要经过井盖、大铁门、钢架、强电线附近。
9. 尽量保持车体水平，不要一侧轮子压坡或上坎。

采样目标：

```text
最低：5000 点
推荐：15000 到 30000 点
频率：约 40 Hz
```

合格关键不是点数越多越好，而是方向覆盖连续、均匀、干扰少。

### 4.2 校准后验证动作：CALIBRATED 90 度停顿

用途：验证写入参数后的实际效果。

要求：

1. 固件切到 `imu_mag_send_calibrated_data_to_pc()`。
2. 每次旋转约 90 度后停 2 到 3 秒。
3. 顺时针完成一圈。
4. 如需更严格，可再逆时针完成一圈。
5. 脚本自动识别每个停顿平台段。

验证重点：

```text
相邻停顿角度差是否约 90 度
每个停顿段半径是否一致
拟合中心是否接近 0
Z 轴是否随方向剧烈变化
```

## 5. GUI 脚本功能设计

推荐技术方案：`PySide6 + pyqtgraph + pyserial + numpy`。

选择原因：

- pyqtgraph 适合实时刷新，比 matplotlib 更适合 40 Hz 数据流。
- PySide6 做按钮、串口列表、状态栏、表格报告更方便。
- 串口读取和绘图可以分线程，避免界面卡顿。

### 5.1 主界面布局

界面包含：

```text
顶部工具栏：串口选择、刷新串口、波特率、数据模式、打开/关闭
左侧状态区：样本数、接收频率、当前 x/y/z、当前 yaw、当前半径
中间绘图区：XY 实时散点、拟合椭圆、当前点、方向覆盖图
右侧质量区：方向桶、最大缺口、半径比、残差、Z 范围、动作提示
底部操作区：开始采集、结束采集、保存数据、保存截图、自动选窗、拟合、写入参数
```

### 5.2 串口自动扫描

功能：

- 自动扫描可用 COM 口。
- 显示端口名、描述、VID/PID。
- 默认选择上次成功使用的端口。
- 打开失败时显示明确错误。
- 支持断线自动重连，但不能丢失已采数据。

### 5.3 数据解析

C 端发送格式：

```text
%.2f,%.2f,%.2f\r\n
```

解析规则：

- 支持 `x,y,z`。
- 支持前面带时间戳的 `[timestamp] x,y,z`。
- 忽略空行和非三元数字行。
- 解析失败计数，不弹窗刷屏。
- 保存时保留接收到的小数精度，不做 int 转换。
- 文件保存使用 UTF-8，数值建议保存 6 位小数。

注意：C 端当前 `%.2f` 已经限制了发送精度。脚本不能恢复丢失精度。如果后续需要更高拟合精度，C 端发送格式建议改为 `%.6f` 或直接发送整数 raw。

### 5.4 实时绘图性能方案

数据频率约 40 Hz，绘图不需要每条数据全量刷新。

设计：

- 串口读取线程只负责解析和入队。
- 主线程用定时器 10 到 20 Hz 刷新图像。
- 使用环形缓冲区保存最近 N 点用于实时显示。
- 全量数据只用于保存和离线分析。
- XY 散点超过 10000 点时实时图降采样显示。
- 当前点用醒目标记。
- 拟合椭圆和质量指标每 0.5 到 1 秒更新一次。
- 不频繁 clear plot，优先更新已有曲线数据。

### 5.5 采集控制

按钮状态：

```text
打开串口
开始采集
暂停显示
结束采集
保存数据
保存截图
```

开始采集时：

- 清空当前采集缓存。
- 记录开始时间。
- 锁定数据模式。
- 创建本轮 session ID。

结束采集时：

- 自动保存数据。
- 自动保存元数据 JSON。
- 自动生成质量报告。
- 可选保存当前绘图截图。

保存文件建议：

```text
track_data/mag_raw_YYYYMMDD_HHMMSS.txt
track_data/mag_raw_YYYYMMDD_HHMMSS.meta.json
track_data/mag_raw_YYYYMMDD_HHMMSS.png
track_data/mag_raw_YYYYMMDD_HHMMSS_report.txt
```

calibrated 模式同理使用 `mag_calibrated_...` 前缀。

## 6. 自动分析功能

### 6.1 RAW 模式分析

RAW 模式用于正式拟合。分析内容：

- 样本数。
- X/Y/Z 范围。
- XY 椭圆中心。
- 软铁矩阵。
- 半长轴、半短轴、轴比。
- 方向覆盖。
- 最大角度缺口。
- 自动最佳窗口。
- 是否允许写入参数。

RAW 模式允许执行：

```text
自动选窗
2D 拟合
生成 header preview
写入 code/ins/calibration_params.h
```

### 6.2 CALIBRATED 模式分析

CALIBRATED 模式只用于验证，不允许直接写参数。

分析内容：

- 拟合中心是否接近 0。
- 从拟合中心计算的半径比。
- 每个停顿平台段的 yaw、半径、Z 均值。
- 相邻停顿角度差。
- 是否存在 Z 轴异常变化。
- 当前参数是否存在非对角方向错误或缩放不足的迹象。

如果用户确实需要从 calibrated 数据反推 raw，只能生成诊断结果，不写入固件。

## 7. 参数写入规则

正式写入只能来自 RAW 数据。

2D 写入策略：

```text
更新 MAG_HARD_IRON_X
更新 MAG_HARD_IRON_Y
保留 MAG_HARD_IRON_Z
更新 MAG_SOFT_IRON_XX
更新 MAG_SOFT_IRON_XY
MAG_SOFT_IRON_XZ = 0
更新 MAG_SOFT_IRON_YX
更新 MAG_SOFT_IRON_YY
MAG_SOFT_IRON_YZ = 0
MAG_SOFT_IRON_ZX = 0
MAG_SOFT_IRON_ZY = 0
保留或继承 MAG_SOFT_IRON_ZZ
更新 MAG_FIELD_STRENGTH
```

写入前必须显示 diff：

```text
旧 hard iron -> 新 hard iron
旧 soft iron -> 新 soft iron
旧 field -> 新 field
质量指标
输入数据文件
选中窗口范围
```

写入后自动执行验证命令，确认 header 可读且参数生效。

## 8. 验收标准

### 8.1 RAW 拟合窗口验收

```text
样本数 >= 5000
方向桶 >= 34/36
最大角度缺口 <= 30 deg
角度跨度 >= 330 deg
校正后半径比 <= 1.15
残差 <= 3.0%
soft iron 数值合理，通常 0.75 到 1.30 范围内
非对角项对称：XY 和 YX 接近
```

### 8.2 CALIBRATED 验证验收

```text
停顿角度差：80 到 100 deg 可接受
拟合中心：abs(x) 和 abs(y) 尽量小于 50
停点半径 max/min <= 1.12 可接受，<= 1.08 优秀
停点半径 CV <= 6% 可接受，<= 4% 优秀
Z 均值差超过 500 时，标记为 3D 效应风险
```

## 9. 实施步骤

### 第一步：修正数据模式和 logger

- 给 `mag_logger.py` 增加 `--mode raw/calibrated`。
- 文件名和文件头随模式变化。
- 元数据记录 C 端期望函数名。

### 第二步：开发 GUI 原型

- 自动扫描串口。
- 打开串口并接收数据。
- 实时 XY 绘图。
- 开始/结束采集。
- 自动保存数据和截图。

### 第三步：接入自动分析

- 复用 `mag_calibrate.py` 的 2D 拟合函数。
- 复用严格选窗逻辑。
- 新增平台段检测。
- 新增 raw/calibrated 模式防错。

### 第四步：参数写入与验证

- GUI 中展示 header preview。
- 写入 `code/ins/calibration_params.h`。
- 写入后调用验证逻辑。
- 提示同步 ADS 和重新编译下载。

### 第五步：现场流程固化

- RAW 连续旋转采集。
- 自动拟合并写入。
- CALIBRATED 90 度停顿验证。
- 输出最终报告。
